# Docker 会话认证方案（仅设计，未实施）

> 基线更新：本文最初写于 2026-09-27，当时 Basic Auth 有效。2026-09-29 用户要求暂时关闭公网 Basic Auth；当前网页和控制 API 匿名可访问，且无用户隔离。下方有关“现有 Basic Auth”的迁移步骤仅是历史方案，实施前必须重新设计完整注册、用户归属与登录权限，不得把下文当作当前线上认证状态。本文未实现任何会话功能。

## 1. 目标与不变边界

用短期 Cookie session 避免每个受保护请求重复执行昂贵的 bcrypt 校验，同时保持现有口令强度。**不降低 bcrypt cost、不换弱哈希、不用硬编码放行绕过性能问题。** 登录时仍执行现有强度的密码校验，并加入有界并发、速率限制及失败退避，避免登录请求耗尽 Worker。

仅覆盖独立 Docker 的 `stt.151077.xyz` 网页/控制 API。`upload.151077.xyz` 保持 tus 上传票据与短期签名读取；不能要求 Gladia 带浏览器 Cookie，也不能把上传域开放为任意代理。Vercel 是独立不变的回滚产品，不设置 `NAS_PREVIEW_*`。Caddy 公网 80/443、loopback 8081 的 Sub2API allowlist、现有 Tunnel 和 worker/tusd 无宿主机端口发布的边界不变。

## 2. 拟议接口（不是已存在的 API）

| 接口 | 方法 | 行为 |
|---|---|---|
| `/login` | GET | 登录页；不暴露配置、用户名是否存在或内部错误 |
| `/auth/login` | POST | 同源登录、限速并验证密码；成功创建新 session 并设置 Cookie，失败统一响应 |
| `/auth/logout` | POST | 校验 CSRF，原子撤销当前 session，清除 Cookie；重复退出幂等 |
| `/auth/check` | GET | 供 Caddy 内部 `forward_auth` 使用；有效会话返回 2xx，否则 401；禁止外网直接访问 |

受保护页面无有效会话时重定向到 `/login`，返回地址只允许同源相对路径，防止开放重定向。API 无会话返回 JSON **401**，不返回 HTML/302；权限不足返回 403。认证服务异常时 fail closed（例如 503），不得把异常当作允许。只豁免明确列出的登录资源；不得通过宽泛 `/auth/*` 豁免暴露内部 check 或管理功能。

## 3. Session 与 Cookie

- 建议使用密码学随机的不透明 session ID，服务端仅保存其摘要、用户、创建时间、绝对过期时间、空闲过期时间及撤销状态。不要把口令或 API Key 放入 Cookie。
- 使用专用会话密钥；与媒体 HMAC、上传票据、代理认证及 provider 密钥严格分离。以受限权限服务端配置提供，不进入 Git、日志、前端 bundle 或 URL。
- Cookie 建议名 `__Host-video2text_session`，设置 `HttpOnly; Secure; SameSite=Strict; Path=/`，不设置 Domain，不跨 `stt`/`upload` 共享。不存入 localStorage。注销以相同属性和 `Max-Age=0` 清除。
- 初始建议空闲过期 30 分钟、绝对过期 12 小时；均为待评审设计值，不是现网配置。服务端强制过期，Cookie 过期不是唯一校验；对时钟偏差设明确界限。
- 登录成功必须重建 session，防止 session fixation。续期/轮换原子执行；并发旧请求不能让已注销会话复活，必要的短暂交叠窗口必须有界。
- 密钥支持带版本轮换，新会话使用新密钥，旧密钥仅在受限窗口验证；泄漏时立即撤销而非等待自然过期。口令变更、管理员撤销或安全事件能吊销全部相关会话。
- 服务重启/多进程应共享一致的持久会话与撤销存储，不能依赖各进程独立内存；日志只记录脱敏事件，不记录 Cookie、密码、CSRF token 或完整认证头。

## 4. CSRF 与反向代理

`SameSite=Strict` 只是防线之一。所有修改状态的请求（登录、退出、创建任务、重试、删除等）严格校验 Origin；必要时以受控 Referer 兜底，并要求会话绑定的 CSRF token/header。登录使用预会话 CSRF 防护，不能因尚未登录而跳过。GET/HEAD 不应产生状态变更，拒绝跨站表单和宽泛 credentialed CORS。tus 仍按既有短期票据、对象绑定和精确 Origin 策略验证。

Caddy 拟通过内部网络 `forward_auth` 调用认证检查端点，在静态页、API、下载等所有受保护 handler 之前完成检查。登录和必要静态资源使用精确路由；认证 handler 与根重定向放入明确顺序的 route，不能依赖 Caddy 普通指令的书写顺序。由受信任代理区分页面重定向与 API 401。

清除客户端伪造的身份/转发头，仅信任 Caddy 注入且限定上游的身份信息。检查原始请求方法/URI 时使用受信任代理提供的值。内部 check 无宿主机端口，不允许由 upload 域或其他通配路由转发访问；Worker 控制 API 继续保留纵深鉴权，不能以仅改 Caddy 代替权限检查。

## 5. 无中断迁移与回滚（未来实施顺序）

1. 固定当前可回滚代码/镜像和经脱敏确认的配置版本；不改变磁盘布局、Vercel、Sub2API 或 Tunnel。准备兼容旧版本的增量会话表，禁止破坏性 schema 迁移。
2. 在独立测试环境或明确受限的 canary 路由部署会话服务；线上 Basic Auth 继续保护全部旧路径。新认证未就绪时不扩大豁免。
3. 完成下面的路由/安全/并发测试，再准备受保护的双版本切换。避免直接重建单 Worker 导致在途任务或上传中断；需要滚动/蓝绿时，将认证控制面与唯一任务执行者隔离，不能意外启动两个执行者重复付费提交。
4. 先验证 Caddy 配置，再使用平滑 reload 切换受控流量；旧鉴权配置和旧服务保持可恢复。在途 tus 上传、Gladia 读取、状态轮询和结果下载应继续工作。
5. 监控认证错误、延迟、会话失败、队列及任务重复执行；超过预定阈值立即恢复旧 Caddy/认证配置，重新启用完整 Basic Auth 保护并撤销新会话。不得为了回滚临时开放匿名入口。
6. 确认回滚后仍可访问既有任务和结果；会话表可保留但旧版不得依赖它。公开入口、内部接口和跨站请求重新验证，稳定后再另行批准删除旧路径。

若无法提供不间断切换及回滚的实测证据，则不宣称“无停机已完成”，也不直接切换现网。

## 6. 验收矩阵（均待实施验证）

- 未登录：`/`、页面、Job URL 跳转登录；控制 API/结果 API 返回 401；内部 `/auth/check` 公网不可达；URL 编码、重复斜杠和子路径不能绕过。
- 登录/退出：正确与错误口令、限速、重复退出、session fixation、过期/撤销/密钥轮换、重启、多进程一致性；Cookie 属性和缓存 `no-store` 正确。
- CSRF：跨站登录/退出/创建任务、缺失或错误 token、伪造 Origin/代理头、开放重定向全部被拒绝；合法同源请求可用。
- 并发/性能：多个浏览器标签同时轮询、并发登录、注销与续期竞态、上传与长任务并行；量测吞吐、尾延迟、bcrypt 校验次数与 Worker 饥饿，不用过短超时掩盖实测行为，不降低 bcrypt 强度。
- 数据平面：tus PATCH/HEAD 续传、预检、票据过期/跨对象拒绝；Gladia 无 Cookie 时仍可读取有效签名媒体，错误/过期签名被拒绝；签名不出现在日志。
- 网络：分别验证 loopback 8081 allowlist、本机正确 SNI 的 TLS、公网两个域名；worker/tusd 仍无发布端口，Tunnel/Sub2API/Vercel 行为不变。
- 故障/回滚：认证服务失败、存储不可用、Caddy reload 失败、旧镜像恢复；均不匿名放行，不丢在途任务，不重复提交付费调用。保存脱敏结果与代码版本，不预填通过或测试数量。
