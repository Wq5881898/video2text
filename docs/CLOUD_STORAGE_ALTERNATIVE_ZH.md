# Web 云端存储备选方案（预研）

> 状态：预研完成，暂不实施  
> 记录日期：2026-09-19  
> 当前决策：继续使用现有 Vercel Web + Vercel Blob，先观察实际体验。

## 1. 目的

本文记录一个可在未来一次性落地的替代方案。当 Vercel Blob 的容量、封停或稳定性持续影响使用时，将网页端迁移为：

- Ubuntu 运行网页后端、任务状态和媒体处理；
- Cloudflare Tunnel 只承载网页和小型 API 请求；
- Cloudflare R2 承载音频临时文件；
- 浏览器直接上传 R2，不让大文件经过 Tunnel 或 Ubuntu；
- Gladia 从 R2 临时地址读取音频；
- 转写成功后立即删除音频，异常文件最多保留 48 小时。

当前阶段不修改现有程序、不创建 R2、不迁移数据，也不改变生产地址。

## 2. 为什么不直接通过 Cloudflare Tunnel 上传

Cloudflare Tunnel 适合访问 Ubuntu 上的网页和 API，但大文件仍经过 Cloudflare 代理，普通套餐的单请求上传限制约为 100 MB。现有 Vercel Blob 使用浏览器直传，单文件可以明显超过 100 MB；将音频改为通过 Tunnel 上传会造成能力倒退。

因此必须分离两类流量：

- 控制流：创建任务、查询状态、查看结果，经过 Tunnel；
- 数据流：音频文件，浏览器直接上传 R2，不经过 Tunnel。

## 3. 目标架构

```text
浏览器
  |-- 网页、创建任务、查询状态 --> Cloudflare Tunnel --> Ubuntu
  |
  `-- 临时签名上传地址 ----------> Cloudflare R2
                                            |
                                            `--> Gladia 读取音频

Gladia 结果 --> Ubuntu --> 翻译/合并 --> TXT 或 SRT --> 浏览器
```

R2 是 Cloudflare 的对象存储，定位与当前 Vercel Blob 相同，不是 Tunnel。R2 支持浏览器使用短期签名 URL 直接上传，并支持大型文件的分段、续传和失败重试。

## 4. 处理流程

1. 浏览器向 Ubuntu 请求一个短期有效、仅允许写入指定对象的 R2 上传凭证。
2. 浏览器直接把文件上传到 R2；密钥不会发送给浏览器。
3. 上传完成后，浏览器只把对象编号、文件名和参数提交给 Ubuntu。
4. Ubuntu生成短期读取地址并提交给 Gladia。
5. 未超过 Gladia 时长限制的文件由 Gladia 直接读取。
6. 超过 Gladia 约 8,100 秒限制的文件由 Ubuntu 临时下载并按时长切分，各段分别转写，再按时间轴合并 TXT/SRT。
7. 转写和结果生成成功后立即删除 R2 原始音频及临时分段。
8. 失败任务保留音频供重试，但最多保留 48 小时；定时任务负责兜底删除。

文件切分以媒体时长为准，不以文件大小代替时长判断。网络 multipart 仅用于可靠上传，不等于 Gladia 的媒体切分。

## 5. 容量和费用理解

R2 免费存储额度是每月 10 GB-month，不是每次 10 GB，也不是每月累计只能上传 10 GB。它计算“占用空间 × 保存时间”。只要音频处理后及时删除，即使每月累计处理的数据较多，实际存储占用仍可能很低。

未来实施时采用 R2 Standard，并设置费用告警。不能把免费额度当成硬性容量保证；超出免费额度后应允许小额计费或主动停止新任务，避免无提示中断。

## 6. 生命周期策略

- 成功任务：确认 Gladia 已完成读取并产出结果后，立即删除原始音频和分段。
- 可重试失败：最长保留 48 小时。
- 无法恢复失败：确认错误后立即删除。
- 未完成 multipart：配置 R2 生命周期规则自动清理，并在实施时验证平台允许的最短周期。
- TXT/SRT：体积很小，可按产品需要延长保留；不得与大音频使用同一清理规则。
- 定时清理：必须独立于用户访问，由 Ubuntu 定时任务或受控的云端调度器执行。

## 7. 安全要求

- R2、Gladia 和翻译模型的完整密钥只保存在 Ubuntu 环境变量或密钥管理中。
- 浏览器只获得短期、单对象、单操作的签名 URL。
- 上传文件名由服务端生成唯一对象键，原始文件名只作为显示信息。
- 限制允许的媒体类型、单文件大小、上传次数和签名有效期。
- R2 bucket 默认不公开；Gladia 使用短期签名读取地址。
- 日志不得记录密钥和完整签名 URL。

## 8. 迁移触发条件

满足任一条件时再启动实施：

- Vercel Blob 再次因存储或用量限制阻断生产使用；
- 即时删除加 48 小时兜底清理后，仍频繁接近 Vercel 配额；
- Vercel 的成本、超时或运行限制明显高于 Ubuntu + R2；
- 需要完全掌控任务队列、日志、重试和模型配置。

如果现有 Vercel 方案在清理机制下运行稳定，则不为迁移而迁移。

## 9. 未来一次性实施清单

1. 创建私有 R2 bucket、最小权限 API Token、CORS 和生命周期规则。
2. 在 Ubuntu 使用 Docker Compose 部署 Web、Worker、任务数据库和定时清理进程。
3. 增加 R2 multipart 初始化、分段签名、完成和取消接口。
4. 前端增加断点续传、失败重试和明确的上传进度。
5. Gladia 改为读取 R2 临时 URL；保留长音频时长切分和结果合并。
6. 成功路径增加即时删除，失败路径增加 48 小时兜底清理。
7. 增加存储量、失败任务、清理结果和费用告警。
8. 使用小文件、超过 100 MB 文件、超过 8,100 秒文件、Safari 中断恢复分别做自动化测试。
9. 先使用测试子域灰度运行，验证后再切换正式域名。
10. 保留 Vercel 版本作为回滚入口，稳定运行一段时间后再决定是否下线。

## 10. 验收标准

- Safari、iOS Chrome 和桌面浏览器均能上传超过 100 MB 的文件。
- 上传数据不经过 Cloudflare Tunnel 和 Ubuntu Web 进程。
- 网络中断后能够重试失败分段，而不是重新上传整个文件。
- 超过 8,100 秒的媒体能自动切分并正确合并 TXT/SRT 时间轴。
- 成功任务不会留下音频；失败音频不超过 48 小时。
- Gladia、R2 和模型密钥不出现在前端、下载结果或日志中。
- 自动化端到端测试通过后才允许切换生产域名。

## 11. 尚待实施时确认

- Ubuntu 的公网位置、磁盘和备份策略；
- R2 账号是否启用付费及费用上限；
- 任务状态使用 PostgreSQL、SQLite 还是其他持久化服务；
- TXT/SRT 的保留期限；
- 超长音频临时分段在 Ubuntu 本地磁盘的空间上限；
- 正式切换窗口和回滚时限。

## 12. 当前结论

现阶段继续使用现有 Vercel 方案并观察，不做迁移。未来若决定实施，应严格采用“Tunnel 管控制流、R2 管文件数据流”的架构，不采用“浏览器通过 Tunnel 上传大音频”的方案。
